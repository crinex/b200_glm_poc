# 실험 가이드 — 재현 방법

빈 인스턴스에서 측정까지, 그리고 `experiments.conf` 로 실험을 정의하는 법.

---

## 1. 세팅 (인스턴스당 1회)

```bash
# /workspace 가 없는 프로바이더면 먼저:
sudo mkdir -p /ephemeral/workspace && sudo ln -s /ephemeral/workspace /workspace

git clone https://<PAT>@github.com/crinex/b200_glm_poc.git /workspace/b200_glm_poc
cd /workspace/b200_glm_poc
bash setup/setup_all.sh
```

`setup_all.sh` 가 프로바이더를 감지해 (드라이버 <580 / venv 없음 / FM 비활성이면)
`setup_deploygpu.sh` 를 먼저 돌리고, 이어서 vLLM·모델 704GB·gen8k 1,024장·
하드웨어 지문을 준비한다. 10~40분 (모델 다운로드 속도에 따라).

---

## 2. 실험 실행

`bench/experiments.conf` 를 편집한 뒤:

```bash
# 백그라운드 권장 (SSH/터널 끊겨도 계속)
setsid nohup bash bench/run_experiments.sh > /workspace/logs/experiments.out 2>&1 &
tail -f /workspace/logs/experiments.out
```

실험마다 `/workspace/results/<이름>_sweep/` 에 남는 것:
`sweep_summary.md`(결과) · `server_args.txt`(실제 서빙 인자) ·
`config.txt`(실행 옵션) · `run_output.txt`(전체 출력) · `fingerprint.txt`(하드웨어).
전체 요약(4지표): `/workspace/results/experiments_summary.md`.

---

## 3. experiments.conf 작성법

한 줄 = 실험 하나. `<이름>  <KEY=VAL> ...`

### 옵션 키

| 키 | 기본 | 의미 |
|---|---|---|
| `TP=` | 8 | Tensor Parallel |
| `DP=` | 1 | Data Parallel. **TP×DP = 8** (GPU 수) 이어야 함 |
| `NO_EP=1` | (EP 켬) | Expert Parallel 끄기 |
| `NO_MTP=1` | (MTP 켬) | MTP 끄기 |
| `SPEC_TOKENS=` | 1 | MTP draft 토큰 수 |
| `SWEEP=` | 4,8,16,32,64,128,256 | 측정 concurrency |
| `MAX_TOKENS=` | 1024 | OSL (바꾸면 기존 결과와 비교 불가) |
| `EXTRA_ARGS="..."` | — | 임의 vllm serve 인자 (따옴표 필수) |

고정(항상): Weight FP8 · KV fp8 · max-model-len 16384 · max-num-seqs 256 ·
gpu-util 0.93 · async-scheduling · ignore_eos · gen8k 1,024장.

### 병렬화 구성별 예시

```
# TP=8 · EP1 · MTP spec1  (저지연 기본 구성)
ref           NO_EP=1 SPEC_TOKENS=1

# TP=8 · EP1 · MTP 없음  (기준선)
baseline      NO_MTP=1 NO_EP=1

# TP=2 · DP=4 · EP8 · MTP spec1  (고처리량 구성, 세션 최고)
dp4tp2_ep8    TP=2 DP=4 SPEC_TOKENS=1

# 임의 서버 인자 추가
kvup          NO_EP=1 SPEC_TOKENS=1 EXTRA_ARGS="--gpu-memory-utilization 0.95"
```

### 값 이름 주의 (실측으로 확인된 함정)

- `--moe-backend` 값은 **소문자**: `deep_gemm`, `flashinfer_cutlass`,
  `flashinfer_trtllm`(기본 자동). 로그의 대문자 `DEEPGEMM` 은 내부 표시일 뿐
- `--data-parallel-size` 를 쓰면 러너가 `--api-server-count 1` 을 자동 추가한다.
  없으면 API 서버가 DP 수만큼 떠서 기동 타임아웃 (실측 실패)
- `TP×DP` 가 8 이 아니면 기동 실패 (GPU 8장)

## 4. 재현: 서버 E 3구성 (2026-09-02)

`experiments.conf` 에서 아래 3줄 주석 해제 후 실행:

```
p0_ref        NO_EP=1 SPEC_TOKENS=1
p1_mtp2       NO_EP=1 SPEC_TOKENS=2 SWEEP=32,128,256
dp4tp2_ep8    TP=2 DP=4 SPEC_TOKENS=1
```

기대 결과 (Output TPS /server, 서버 E 실측):

| conc | TP8·EP1·MTP1 | TP8·EP1·MTP2 | TP2·DP4·EP8·MTP1 |
|---|---|---|---|
| 32 | 1,877 | 1,514 | 1,249 |
| 64 | 1,948 | — | 1,883 |
| 128 | 2,193 | 2,338 | **2,494** |
| 256 | 2,174 | 2,278 | **3,188** |

풀스펙 인스턴스(1000W, 드라이버 595)라면 ±수% 내 재현되어야 한다.
서버가 다르면 수치가 안 맞을 수 있다 (지문 대조 필수 — FINDINGS §0-1, §6-2).

---

## 5. 결과 해석 핵심

- **Output TPS** = 서버 총 처리량. **Input TPS = Output × (ISL/OSL) = ×8**
  인 파생 지표라 따로 안 봐도 됨 (FINDINGS §4)
- **TPOT / Interactivity** = 개별 사용자 체감 속도. DP 를 키워도 rank당 TP 가
  작으면 개선 안 됨. "서버 총량"과 "개인 체감"을 구분할 것
- **노이즈 바닥 ±5%**: 동일 구성도 conc 별로 ±5% 흔들린다. 그 이내 차이는
  잡음으로 볼 것 (서버 D↔E 기준선 재현으로 확인)

---

## 6. 운영 규칙 (반드시)

- **서버를 SIGKILL 하지 말 것.** NCCL P2P 교착 → 이후 모든 기동 실패, 인스턴스
  재시작만이 복구 (FINDINGS §0). 벤치만 실패했으면 `SKIP_BOOT=1` 로 벤치만 재실행
- 정상 정리: `bash serve/gpu_reset.sh` (SIGTERM 우선)
- 진행 확인: `tail -f /workspace/logs/experiments.out`,
  실시간 처리량: `tail -f /workspace/logs/vllm_<태그>.log | grep -E "Running:|acceptance"`

---

## 7. 기각된 구성 (재실험 금지)

| 구성 | 사유 |
|---|---|
| TP<8, DP>1 (예: TP=4 DP=2) | 복제본당 2~4장에 700GB 모델 안 들어감 (EP 없이는 OOM) |
| mnbt 상향 (8192→16384+) | 효과 없음 (§7) |
| `--disable-custom-all-reduce` | 성능 역방향 + 과거 교착 이력 |
| EP8 (TP=8 위에서) | 저~고 conc 전 구간 -4~-13% |

주의: **TP=2·DP=4·EP8 은 기각 아님** — 고conc(≥128)에서 우세. 위 "TP<8 불가"는
EP 를 안 켠 경우이고, EP8 이 전문가를 흩어 메모리를 낮추면 기동 가능하다.
