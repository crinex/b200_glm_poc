# 커널 최적화 계획 — "5배" 를 물리 예산으로 분해 (2026-09-02)

## 1. decode 1스텝 예산 (conc128, MTP1 → 스텝당 256 토큰, TP8, B200 HBM 8 TB/s)

config.json 실값: 78층(dense 3 + MoE 75), hidden 6144, expert 256 × top-8 + shared 1, moe_inter 2048,
MLA kv_lora 512 + rope 64, DSA index_topk 2048, 인덕서 full 21층(IndexShare), MTP 1층, vocab 154,880.
가중치 합 742GB(계산) = 로그 실측(92.7GiB×8) → 모델 검증됨.

| sparse KV 읽기 (쿼리당 2048토큰×576B×78층) | 2.9 | **TP8 은 8장이 같은 KV 를 중복으로 읽음** → DP-attn 이면 0.4 |
| 인덕서 K cache (ctx 9.2k × 128B × 21층) | 0.4 | |
| 컴퓨트 (active ~40B × 256토큰) | 1.1 | 메모리와 겹침 — **컴퓨트 바운드 아님** |
| all-reduce 156회 (3.1MB, ~20µs) | 3.1 | 순차 |
| **루프라인 바닥** | **≈18** | |
| **실측** (TPOT 55ms × accept 1.75) | **≈96** | |
| 실측/바닥 | **5.3×** | |

→ **"5배" = 루프라인에 거의 도달하라는 뜻.** 커널만으로는 안 되고, 바닥 자체를 낮추는 시스템 변경과 곱해야 한다.
- NVFP4 experts(가중치 ~절반) + DP-attn(KV 중복 제거) → 바닥 ≈ **10ms**
- MTP accept 1.75 → 3.0 이면 같은 스텝 시간에 토큰 1.7×

정직한 판독:
- **커널만(K1~K7)으로는 ~2× 가 상한** (96 → 50ms). 5.3× 갭 전부를 커널이 먹지는 못함.
- **5×는 커널 2× × 시스템 2.5×(MTP·DP/EP·NVFP4·conc↑)의 곱** 으로만 도달 가능. 이 중 시스템 쪽은 메인 실험 축과 겹친다.
- 순서는 **측정 → 큰 덩어리(K1, K2) → 퓨전 묶음(K4~K7) → K3**.

### 7-3. 읽는 법 — 이득의 정체

1. **+47% 는 전부 상주 요청 수에서 왔다.** step 시간은 오히려 132 vs 128ms 로 같다. TP8 은 KV 한계 ~150 으로 conc256 이 실제 150 만 돌았고, DP4 는 256 전부 돌았다. 예측(KV 중복 제거)이 그대로 맞음.
2. **step 자체는 빨라지지 않았다.** rank 당 128 토큰을 132ms 에 처리 — TP8 이 300 토큰을 128ms 에 처리한 것보다 토큰당 2.4× 비효율. 원인 후보: (a) EP a2a 통신(기본 백엔드), (b) rank 당 배치가 작아 launch/CPU 오버헤드 비중↑, (c) DP rank 간 스텝 동기화 대기, (d) TP2 라 GPU 당 가중치 99GB 를 혼자 읽음 (12.4ms 바닥).
3. **저concurrency 는 −33% 손해** — 요청 4개가 rank 하나에 몰리고 그 rank 는 TP2 의 느린 가중치 읽기를 감수. 운영 정책이 갈림: conc<64 는 TP8, ≥128 은 DP.
4. 루프라인 갭 6.1× — DP4 에서 **커널·통신 오버헤드가 더 커졋다**. 커널 작업의 여지도 그만큼 커진 것.

### 7-4. 5× 를 다시 환산

| 기준 | 목표 tok/s | conc256·accept 1.76 에서 필요한 step | 바닥 대비 |
|---|---|---|---|
| 원 기준 2,251 × 5 | **11,250** | 40 ms | 1.8× (커널만으론 비현실) |
| 〃, accept 2.7 (MTP3) | 11,250 | 61 ms | 2.8× — **커널 2.2× 개선이면 도달** |
| 〃, accept 2.7 + 상주 384 (KV 428 여유) | 11,250 | ~92 ms (rank 192 tok) | 현실적 |
| 새 기준 3,188 × 5 | 15,940 | — | 루프라인 근접 요구, 비현실 |

**곱셈 스택 (갱신)** — 시작점 DP4 conc256 = 3,188

| 단계 | step | 토큰/step | Output tok/s | 배수(vs 2,251) |
|---|---|---|---|---|
| 현재 DP4TP2 conc256 | 132 | 1.76×256 | 3,188 | 1.4 |
| + MTP3 (accept 2.7, draft 비용 +8%) | 143 | 2.7×256 | 4,830 | 2.1 |
| + 상주 384 (step +25% 가정) | 178 | 2.7×384 | 5,830 | 2.6 |
